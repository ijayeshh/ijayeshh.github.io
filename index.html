Agentic RAG · Finance

Self-Evolving Topic Ontology for Earnings Calls

Problem
Earnings call transcripts are long and unstructured. Analysts need financial topics tracked consistently across quarters, without a fixed taxonomy that goes stale.
Approach
Reproduced Bloomberg's paper “Agentic Retrieval of Topics and Insights from Earnings Calls”. A LangGraph Supervisor routes ingestion through Retriever and Ontologist agents that grow a topic tree in SQLite/ChromaDB, and routes questions through RAG and a Judge agent with a citation-enforcing retry loop. It runs on rate-limited Groq inference and is exposed to external clients through an MCP server.
Results
  • Ontology coherence 0.48 vs 0.18 random-parent baseline
  • Retrieval hit@10 of 0.80
  • LLM-as-judge faithfulness suite with LangSmith tracing

LLM Security · Banking

SentinelBank: Self-Hosted Banking Copilot with Layered Guardrails

Problem
Relationship managers want to query customer portfolios in plain English, but bank customer data can't go to a third-party API. Prompt injections can also arrive inside retrieved data, not just in what the user types.
Approach
A fully on-prem LangGraph agent on Llama 3.2 3B (Ollama, 4 GB GPU), using text-to-SQL and vector RAG over PostgreSQL/pgvector. Every request passes through layered rails: Presidio PII redaction, prompt-injection scans on input and tool results, AST-level SQL validation, entitlement enforcement, human-in-the-loop approval, and a SHA-256 hash-chained audit log.
Results
  • 84.6% precision on a 30-case red-team suite
  • Unseen-attack detection reported separately (4/8 held-out vs 6/6 authored), so it isn't averaged away
  • Guardrails are 4.9% of median end-to-end latency, backed by 439 offline tests

Grounded QA · Legal

Hybrid Retrieval and NLI Verification for Legal Contracts

Problem
In legal QA a fluent but unsupported claim is worse than no answer, so faithfulness has to be measurable rather than assumed.
Approach
Citation-grounded QA over CUAD contracts. Hybrid retrieval combines BM25 and FAISS embeddings with reciprocal rank fusion and cross-encoder reranking. Mistral answers only from retrieved spans, and each answer is split into atomic claims. A LangGraph loop runs an NLI gate on every claim against its cited span and rewrites unsupported ones. Includes an MCP search tool, Langfuse tracing, and promptfoo/pytest CI.
Results
  • 0.875 accuracy on an unseen, contamination-controlled LegalBench task
  • Dual faithfulness scoring, NLI 0.42 vs LLM-judge 0.78, to quantify how reliable each metric is (sample snapshot)
  • Citations scored against CUAD gold spans at the character-offset level

Fine-tuning · Alignment

LLM Alignment with Direct Preference Optimization

Problem
Steering a model's responses usually means RLHF: a separate reward model plus a reinforcement-learning loop, which is heavy and brittle to tune.
Approach
Aligned Qwen2.5-7B-Instruct with DPO directly on (prompt, chosen, rejected) pairs about ethical questions around AI-generated art. The model is loaded in 4-bit with Unsloth, with LoRA adapters on the attention and MLP projections, and trained with TRL's DPOTrainer.
Results
  • Pre- vs post-alignment outputs on held-out questions compared with an LLM-as-a-judge framework
  • 7B alignment that fits a single Colab-class GPU via 4-bit quantization and PEFT
  • Configurable epochs, data size and label balance for studying alignment strength

RAG · Legal

Metadata-Enriched Retrieval for Legal QA

Problem
Legal sources conflict across jurisdictions and years, and plain top-k similarity retrieval quietly mixes them in the same context.
Approach
Built in two stages. The first is a vanilla LangChain RAG baseline (bge-small embeddings, Chroma, Groq Llama 3.1). The second is a policy layer that stamps jurisdiction, effective date and authority rank onto every chunk, which enables filtering by jurisdiction, recency and authority before generation.
Results
  • Runnable baseline and policy-layer pipelines side by side for comparison
  • Metadata validated on every chunk at index time (65 chunks from 16 federal and California documents)
  • Stress-test queries that make the conflicting-source problem visible
  • LangChain
  • ChromaDB
  • Groq
  • Hugging Face
  • bge-small

Representation Learning

Self-Supervised Contrastive Learning

Problem
Labelling images is slow and expensive. Can representations learned from unlabeled images compete with a fully supervised model?
Approach
Trained SimCLR (InfoNCE) and Barlow Twins in PyTorch on 100K unlabeled STL10 images using an NVIDIA A100, then ran a logistic-regression linear evaluation on frozen embeddings with 10 to 500 labeled images per class, benchmarked against a supervised baseline.
Results
  • Top-1 validation accuracy: SimCLR 62.17%, Barlow Twins 59.46%
  • Supervised baseline: 58.35%
  • About 50% relative gain across the 10–500 labels-per-class linear evaluation

MLOps · Transfer Learning

End-to-End MLOps for Disease Classification

Problem
A model that only lives in a notebook isn't usable. Training has to be reproducible, and getting to deployment shouldn't be a manual step.
Approach
A binary image classifier built with VGG16 transfer learning (ImageNet weights, frozen base) in TensorFlow/Keras, structured as four DVC stages with MLflow tracking for evaluation. It's packaged as a Dockerized web app, and a GitHub Actions workflow builds and pushes the image to AWS ECR, then deploys it.
Results
  • Push-to-deploy: every commit to main rebuilds, pushes and redeploys the container
  • Reproducible pipeline with tracked evaluation runs in MLflow
  • Pipeline settings and model parameters kept in YAML
